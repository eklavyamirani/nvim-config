# Supply-chain verification

Successful pushes to `main` or `master` produce `nvim-config.tar.gz`, a bundle
of the exact tested Git commit. GitHub signs a build-provenance attestation for
the bundle using the workflow's short-lived OpenID Connect identity. The
attestation uses the SLSA provenance predicate generated by GitHub's official
`actions/attest-build-provenance` action.

Download the `nvim-config` artifact from its workflow run, then verify both its
digest and provenance with GitHub CLI:

```sh
gh attestation verify nvim-config.tar.gz --repo OWNER/REPOSITORY
```

Replace `OWNER/REPOSITORY` with this repository's GitHub name. Verification
checks the artifact against GitHub's transparency log and confirms that its
provenance belongs to this repository. Pull-request workflows run the complete
test matrix but do not publish attestations because untrusted pull requests do
not receive the `id-token: write` and `attestations: write` privileges.
